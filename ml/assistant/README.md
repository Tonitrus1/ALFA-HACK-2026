# Сервис чат-агента: первый этап

**Режим разработки с внешним платным LLM API. Это не версия для сдачи жюри.**
Перед сдачей обязателен отдельный бесплатный способ запуска настоящей LLM с открытыми
весами. Подмена генерации заглушкой это требование не выполняет.

Самостоятельный Python 3.12 / FastAPI сервис: временные сессии, локальный E5 RAG,
Qdrant, BM25 + RRF, SearXNG, чтение официальных страниц, подтверждаемое сохранение
снимков и инструменты синтетического банка. Пользовательского UI нет; Swagger находится
по адресу `http://localhost:8000/docs`.

## Запуск в Docker

Нужны Docker Desktop с Linux containers, Docker Compose и интернет для первоначальной
подготовки, поиска и внешнего LLM API. Практический ресурсный минимум ещё не измерен.
Веса E5 занимают около 470 MB; полный образ с PyTorch существенно больше. PyTorch
использует CPU; пакет из PyPI на Linux может включать неиспользуемые CUDA-зависимости.

Из корня репозитория:

```powershell
cd ml/assistant
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

Заполните `.env`: `ADMIN_API_KEY`, `SEARXNG_SECRET` - независимые случайные секреты,
`LLM_API_KEY` - ваш ключ агрегатора. Не помещайте секреты в Git или коллекцию запросов.
Остальные настройки имеют безопасные значения по умолчанию. Проверить модель и тариф
перед расходами: [карточка агрегатора](https://aitunnel.ru/models/qwen3-30b-a3b).
Цена в расчёте API неизвестна, пока вы явно не зададите тарифы в окружении.

```powershell
docker compose build
# Явная однократная подготовка. Скачивает только E5 и токенизатор, не веса Qwen.
docker compose run --rm --no-deps -e HF_HUB_OFFLINE=0 -e TRANSFORMERS_OFFLINE=0 assistant alfa-assistant prepare-models
docker compose up -d
docker compose exec assistant alfa-assistant seed
docker compose exec assistant alfa-assistant calibrate
```

`calibrate` сохраняет `reports/dense-calibration.json` внутри контейнера и печатает
измеренный `DENSE_MIN_SCORE`. Скопируйте отчёт командой
`docker compose cp assistant:/app/reports/dense-calibration.json reports/dense-calibration.json`,
внесите значение в `.env` и выполните `docker compose up -d --force-recreate assistant`.
В `.env.example` уже записан измеренный порог для включённого корпуса; после изменений
его следует измерить заново. Если переменная не задана, dense-ветка выключена,
работает BM25; случайного порога нет. Набор
калибровки является небольшим development set, а не доказательством качества.

`/health/live` проверяет процесс. `/health/ready` проверяет локальные модели/индекс,
доступность Qdrant/SearXNG и наличие ключа LLM. Проверка health не тратит токены,
не доказывает работоспособность модели у провайдера и внешних поисковых движков.
При неудаче сверки индекса перезапустите сервис после восстановления Qdrant.

Сервис слушает `127.0.0.1:8000`; Qdrant и SearXNG не публикуют порты хоста.
Файлы, SQLite, модельный кеш и Qdrant сохраняются в named volumes. `docker compose down`
сохраняет знания; `down -v` уничтожает volumes. Сессии теряются при каждом рестарте.
Запускается ровно один Uvicorn worker. Несколько реплик пока не поддерживаются.

## Ручная проверка API

Импортируйте `requests/assistant.postman_collection.json` в Postman, задайте
`admin_key` локально. Коллекция последовательно создаёт сессию, ведёт диалог,
предлагает веб-материал, получает кандидата, подтверждает хеш снимка и ищет его в RAG.
Ответ модели не гарантирует, что кандидат появится за один ход: при необходимости
отправьте продолжение. Простой вариант для REST Client: `requests/assistant.http`.
Полное описание: `openapi.json`, интерактивное - `/docs`.

1. `POST /v1/sessions` с `{}`. Сохранить `session_id` и единожды возвращённый
   `session_token`. Токен требуется как `Authorization: Bearer ...`.
2. `POST /v1/sessions/{id}/messages` с
   `{"client_message_id":"unique-1","message":"Какие есть демо-продукты?"}`.
   Клиент передаёт только новое сообщение. Повтор ID с тем же текстом возвращает
   исходный результат (включая сохранённую ошибку), с другим текстом даёт `409`.
3. Для знаний: `POST /v1/admin/knowledge/import`, multipart-поля `metadata`
   (JSON: title, attribution, allowed_use и другие поля Metadata), ровно одно из
   `file` / `text`, необязательно `document_id` для новой версии. Форматы: UTF-8 TXT,
   Markdown, HTML, текстовый PDF. Лимит файла 10 MiB, OCR и защищённые PDF исключены.
4. Импорт создаёт `DRAFT`. После просмотра текста вызовите
   `POST /v1/admin/knowledge/{document_id}/versions/{version}/publish`.
   Управляющие запросы требуют `X-Admin-Key`.
5. Попросите ассистента найти информацию в интернете, прочитать результат и
   предложить сохранить. В ответе появится `pending_actions`. Администратор открывает
   `GET /v1/admin/web-candidates/{id}`, проверяет текст и право использования, затем
   вызывает `/confirm` с точным `sha256`, `attribution`, `allowed_use`. Сохраняется
   скачанный снимок; повторного скачивания при подтверждении нет.
6. `GET /v1/knowledge/search?q=...` с административным ключом возвращает фрагменты,
   метаданные и оценки без вызова LLM. Отзыв - `/revoke`.

Управление demo-пользователем и системником при создании сессии также требует
административного ключа. По умолчанию `demo-user-1` видит компанию `demo-company-1`
и заявки `demo-app-1`, `demo-app-2`; `demo-user-2` - вторую компанию и заявки 3/4.
Это демонстрационная авторизация, не промышленная схема аутентификации.

Системное сообщение редактируется в `prompts/system.txt` (смонтировано read-only).
Изменения применяются к новым сессиям; хеш и параметры модели фиксируются в сессии.
Параметры LLM, URL, порог dense, домены, цены и лимиты настраиваются через окружение.
JSON-массив доменов: `WEB_ALLOWED_DOMAINS=["alfabank.ru","cbr.ru","fincult.info","nalog.gov.ru"]`.

## Локальная разработка и проверки

Нужны Python 3.12 и uv 0.9.5. Команды выполняются в `ml/assistant`:

```powershell
uv sync --frozen --extra test --extra models
uv run alembic upgrade head
uv run alfa-assistant prepare-models
# Настройте QDRANT_URL и SEARXNG_URL для локально доступных экземпляров.
uv run alfa-assistant seed
uv run alfa-assistant calibrate
uv run uvicorn alfa_assistant.main:app --host 127.0.0.1 --workers 1 --no-access-log
```

Обычные тесты не загружают модели и не используют платные API:

```powershell
uv sync --frozen --extra test
uv run ruff check src tests scripts migrations
uv run ruff format --check src tests scripts migrations
uv run pytest -q --junitxml=reports/unit-tests.xml
# Отдельно: настоящий Qdrant, с временной коллекцией, удаляемой по завершении теста.
$env:TEST_QDRANT_URL = "http://localhost:6333"
uv run pytest -q -m integration
# Не более двух платных запросов; без ключа явно SKIPPED.
uv run alfa-assistant smoke-llm
uv run alfa-assistant export-openapi
```

`alfa-assistant reindex` полностью пересоздаёт производный Qdrant-индекс из SQLite.
Выполняйте полный reindex в обслуживании, без одновременной обработки запросов основным
процессом; отдельный CLI-процесс не разделяет его блокировку публикации.
Схема БД изменяется только миграциями Alembic; runtime не вызывает `create_all`.
Сверка индекса выполняется при старте. BM25 вычисляется из активных сохранённых
фрагментов; его IDF использует положительный RSJ-вариант для малого корпуса.

## Границы и поставка

LLM-клиент не делает автоматических повторов и не подменяет модель. Четыре вызова
LLM / шесть инструментов / 60 секунд на ход. Локальный Qwen tokenizer ограничивает
вход 12 000 токенами и удаляет только целые старые ходы; ответ ограничен 1000 токенами.
Источники занимают общий бюджет 2500 токенов, максимум пять. Цитаты проверяются по
идентификаторам переданных источников; это не доказывает правильность каждого тезиса.
При отзыве использованного источника во время генерации текст ответа не выдаётся.

Для пользовательского поиска и ответов доступны только опубликованные `PUBLIC_NOTE` и `WEB` с `is_synthetic=false`. Документы `SYNTHETIC` остаются в административной базе, но не попадают в RAG, историю контекста, цитаты или просмотр источника пользователем. Сохранённые ответы на их основе скрываются при загрузке истории и повторе сообщения с прежним идентификатором.

Веб-поиск: один запрос, до пяти результатов и двух чтений за ход. Только разрешённые
домены и публичные IP, до трёх редиректов, 5 MiB, 10 секунд, без JS. DNS проверяется,
соединение привязывается к проверенному IP, TLS SNI/Host сохраняются, прокси окружения
отключены. Snippets не цитируются как прочитанные страницы. Ошибки поисковых движков,
CAPTCHA и их ограничения не обходятся.

В общую базу разрешено вручную импортировать только публичные или синтетические
материалы. Классификатора персональных данных здесь нет; администратор отвечает за
отбор. ТЗ организатора не включено в пользовательский корпус. Реальные заметки
отделены от синтетических условий и данных бизнес-инструментов.

JSON-логи содержат идентификаторы, хеш системника, времена, токены и коды ошибок.
Секреты, сообщения, тексты, финансовые payloads и reasoning не логируются.
Стоимость вычисляется по фактическому usage и заданным тарифам; при неполных
данных равна `null`, известная часть токенов возвращается отдельно.

- `docs/architecture.md`: компоненты, модель данных и согласование публикации.
- `docs/contract-differences.md`: отличия от прежнего assistant API и будущий адаптер.
- `corpus/manifest.json`: происхождение и допустимое использование стартовых материалов.
- `evaluation/`: 20 русских вопросов и 10 негативных сценариев.
- `reports/verification.md`: фактически выполненные и невыполненные проверки.
- `THIRD_PARTY_NOTICES.md`: модели, библиотеки, сервисы и смоделированные интеграции.

Java-интеграция, UI, кредитное решение, OCR, подача/изменение заявок, подписание,
выдача денег, долговременная история и бесплатный LLM runtime для жюри остаются
в следующих этапах основного проекта. Этот сервис их не реализует.
