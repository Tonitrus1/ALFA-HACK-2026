# Рекомендательная лента финансирования бизнеса

Готовый ML-модуль без UI и пользовательского хранилища. E5 ранжирует единый каталог из 36 законченных русских карточек; реакции и глубина объяснения добавляют фиксированные бонусы. Отдельное приложение, отдельная среда, порт 8002. Risk API на 8001 работает независимо.

Полная передача коллегам: [docs/feed-integration.md](../../docs/feed-integration.md).

Из корня репозитория (Python 3.12):

```sh
./scripts/feed setup
./scripts/feed prepare --download
export ML_INTERNAL_TOKEN='feed-local-example-token-change-me'
./scripts/feed serve
```

Сеть нужна для установки и явного `prepare --download`. После подготовки `serve`, `test`, `rank`, `evaluate` работают локально. Токен в примере — только локальный пример, задайте своё значение для общей среды.

FEED принимает внутренний токен через `X-Service-Token`, как указано в каноническом API. Bearer для этой службы не используется. Публичный `GET /api/v1/feed/saved` и поле `FeedCard.userReaction` описаны в контракте для backend/frontend; публичные endpoints ещё предстоит реализовать.

```sh
./scripts/feed test --with-model
./scripts/feed evaluate
./scripts/feed rank ml/feed/examples/purchase-cost.request.json
./scripts/feed rank ml/feed/examples/purchase-cost.request.json --rules
```

`MODEL`: косинусная близость E5 + `0.05 * clip(helpful - notInterested, -2, 2)` + `0.03` за выбранную глубину. Итоговый порядок ограничивает тему двумя карточками в каждой шестёрке, пока доступны другие темы. Сходство не является вероятностью полезности. При полностью пустом профиле используется вводный `RULES`.

Веса уже подготовлены локально в `.local/feed-bundle/`. Они не включаются в обычный Git: файл весов около 449 MiB. В Git передаются закреплённая ревизия, SHA256 каждого исходного файла, зависимости, маленький кэш векторов и manifest в `release/`. Коллеги воспроизводят комплект одной командой подготовки либо получают всю папку `.local/feed-bundle/` через хранилище артефактов. Во время обслуживания ничего не скачивается.

- `catalog/cards.json` — единственный редактируемый источник карточек и метаданных.
- `catalog/illustrations/` — шесть собственных SVG.
- `catalog/review.json` — содержательный просмотр всего набора исполнителем; банковское согласование не заявляется.
- `model-lock.json`, `requirements.lock.txt`, `release/` — закрепление модели и среды.
- `server.py`, `ranker.py`, `encoder.py` — внутренний API, упорядочивание, E5 CPU.
- `integration.py` — пример клиента backend с проверкой ответа и fallback, формирование карточек из каталога, фильтрация и повтор порции.
- `backend_reference.py` — исполняемый образец семантики реакций для переноса в backend; память процесса не является поставкой пользовательского хранилища.
- `examples/` — снимки реальных запросов/ответов, воспроизводимые по каталогу.
- `fixtures/scenarios.json`, `tests/` — приёмочные сценарии и проверки.
- [Отчёт релевантности и задержки](../../reports/feed-evaluation.json).

Публичные endpoints, cursor, долговечные профили/реакции и совместная приёмка через frontend — часть коллег. Канонические контракты уже расширены в `docs/architecture/contracts/`; UI-прототипа нет.
