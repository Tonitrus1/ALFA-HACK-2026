# Весь сервис на одной VM Selectel

Ветка `deploy/selectel-vm` содержит интерфейс, backend, парольный вход, Risk, Feed, ML bridge, OCR и worker, ассистента, базы и индексы. Поверх общего `compose.yaml` подключается серверный overlay. Локальный запуск сохраняется отдельно.

Новый сервер использует `.env.selectel`, новые пароли и тома проекта `credit-selectel`. Локальные кабинеты, документы, переписки и секреты в эту поставку не входят. На первой установке компании А и Б получают пустые кабинеты.

## 1. Подготовить Selectel

Создайте облачный сервер **Ubuntu 24.04, x86_64**, с постоянным диском, публичным IPv4 и SSH-ключом. Начальная конфигурация для локальной Qwen2.5 3B: **8 vCPU, 16 GB RAM, 160 GB SSD**. RAG-модель работает на CPU на этой VM; внешний API для RAG не требуется. OCR сохраняет прежнюю конфигурацию. На 16 GB весь стек требует замера памяти и времени ответа; это конфигурация для небольшой нагрузки, а не результат нагрузочного теста на Selectel. Сборка выполняется последовательно, чтобы уменьшить расход памяти.

В security group разрешите входящие `22/TCP` с административного IP, `80/TCP` и `443/TCP` для пользователей. Разрешите исходящий интернет для установки пакетов, Docker Registry, первого скачивания моделей и веб-поиска. Назначьте домену A-запись с публичным IPv4 VM; AAAA-запись нужна только при действительно настроенном IPv6. Настройка сети и SSH описана в [инструкции создания сервера Selectel](https://docs.selectel.ru/cloud-servers/create/create-server/) и [документации security groups](https://docs.selectel.ru/en/cloud-servers/security-groups/about/about-security-groups/).

Снаружи публикуются только 80 и 443. Ollama, PostgreSQL, Qdrant, SearXNG, ML, OCR и admin API ассистента не имеют портов хоста. Caddy выпускает и продлевает сертификат для указанного домена и перенаправляет HTTP на HTTPS; DNS и открытые 80/443 обязательны. [Условия автоматического HTTPS](https://caddyserver.com/docs/automatic-https).

## 2. Получить проект и установить Docker

Подключитесь по SSH командой из панели Selectel. Далее используйте пользователя с sudo; для закрытого репозитория понадобится ваш доступ к Git.

```bash
sudo apt-get update
sudo apt-get install -y git python3
git clone --branch deploy/selectel-vm --single-branch https://github.com/Tonitrus1/ALFA-HACK-2026.git credit-service
cd credit-service
sudo sh deploy/selectel/install-docker.sh
```

Установщик предназначен для свежей Ubuntu 24.04 и использует [официальный APT-репозиторий Docker](https://docs.docker.com/engine/install/ubuntu/). Если Docker уже установлен, проверьте `sudo docker compose version`: нужен Compose **2.24.4 или новее**, поскольку overlay удаляет локальный порт gateway через `!reset`. [Правила объединения Compose](https://docs.docker.com/reference/compose-file/merge/).

## 3. Настроить домен, пароли и LLM

Замените домен и адрес почты своими:

```bash
sudo python3 scripts/selectel.py init --domain cabinet.example.com --email admin@example.com
sudo nano .env.selectel
```

`init` генерирует независимые секреты и не заменяет существующие пароли при повторном запуске. Новая конфигурация содержит `LLM_MODE=local` и `LOCAL_RAG_MODEL=qwen2.5:3b`. Оставьте их для запуска Qwen на этой VM: ключ провайдера для RAG не нужен. Только ассистент подключается к внутреннему адресу `http://ollama:11434/v1`, порт модели не публикуется. При обновлении существующего `.env.selectel` добавьте эти две строки явно: файл без `LLM_MODE` сохраняет прежний внешний режим.

Для разрешённого правилами внешнего провайдера можно явно выбрать `LLM_MODE=external` и заполнить `LLM_API_KEY`, `LLM_BASE_URL`, `ASSISTANT_LLM_MODEL`, `OCR_LLM_MODEL`. В этом режиме `up` требует ключ и HTTPS-адрес. Настройки локального `.env` не переносятся в серверную установку. OCR независимо сохраняет `LLM_API_KEY`, `LLM_BASE_URL` и `OCR_LLM_MODEL`: заполните их как раньше. Полный `up` проверяет ключ OCR даже при локальном RAG; этот этап OCR в рамках изменения RAG не переводится на другую модель.

Данные входа создаются в `.local/selectel/cabinet-access.md`: логины `company-a` и `company-b`, отдельный пароль каждой компании. Передайте этот файл получателю отдельно. В Git нет ни реальных паролей, ни LLM-ключей. Cookie сессии имеют `Secure`, `HttpOnly`, `SameSite=Strict`; сервер принимает вход только с HTTPS Origin указанного домена.

Не меняйте имя Compose-проекта у существующей установки: от него зависят имена постоянных томов. Для другого стенда используйте отдельный `init --project ИМЯ` и другой `--env-file ПУТЬ`; эти параметры задаются при создании новой установки.

## 4. Собрать и запустить всё

```bash
sudo python3 scripts/selectel.py config
sudo python3 scripts/selectel.py doctor
sudo python3 scripts/selectel.py up
sudo python3 scripts/selectel.py status
sudo python3 scripts/selectel.py check
```

`up` собирает образы по одному, поднимает все компоненты, дожидается миграций, подготовки моделей и проверок готовности. Первый запуск требует интернета и может занять больше времени из-за загрузки моделей. Кабинет доступен по `https://ВАШ_ДОМЕН`. `check` проверяет настоящий HTTPS, вход обоих аккаунтов, cookie и запрет доступа к чужой компании. Он не отправляет платных запросов LLM. При первом локальном запуске `ollama-init` скачивает около 1,9 GB весов, повторные запуски используют том `ollama-models`. Ошибка загрузки блокирует старт ассистента. Ollama ограничена 6 CPU и 5 GiB RAM, работает с одной моделью и одним запросом одновременно. Контекст 4096 токенов; ограничения RAG и тайм-ауты описаны в [общей инструкции](../../docs/deployment.md#локальная-qwen-3b-без-внешнего-провайдера).

Готовность контейнеров не заменяет проверку генерации. Выполните реальную проверку JSON, инструментов и RAG-ответа с цитатой:

```bash
sudo python3 scripts/integration/local_llm_smoke.py --selectel --env-file .env.selectel
```

После этого проверьте чат и OCR в интерфейсе. Скорость на целевой VM нужно измерить отдельно.

Полезные команды:

```bash
sudo python3 scripts/selectel.py logs
sudo python3 scripts/selectel.py down
sudo python3 scripts/selectel.py up --no-build
```

`down` сохраняет тома. Для серверной установки используйте `scripts/selectel.py`, чтобы каждый раз подключать правильный overlay и `.env.selectel`. Обычный локальный `docker compose up` не является серверной командой этой ветки.

## 5. Обновление и резервное копирование

Перед обновлением:

```bash
sudo python3 scripts/selectel.py backup
git pull --ff-only origin deploy/selectel-vm
sudo python3 scripts/selectel.py up
sudo python3 scripts/selectel.py check
```

`backup` проверяет наличие томов, останавливает сервисы на время холодного копирования, архивирует **все** тома — обе БД, файлы, SQLite ассистента, OCR, индексы, модели и сертификаты — вместе с закрытой копией `.env.selectel` и контрольными суммами. После операции восстанавливает ранее запущенные сервисы. Нужны место для ещё одной полной копии и окно недоступности. Результат: `.local/selectel/backups/ВРЕМЯ/`. Скопируйте каталог резервной копии на отдельное хранилище с ограниченным доступом: в нём есть пароли и пользовательские данные. Копия на диске той же VM не защищает от потери VM.

Для восстановления на **новой VM без существующих томов**:

1. Установите ту же ревизию проекта и Docker. Нужный commit SHA записан в поле `revision` файла `manifest.json` резервной копии.
2. Перенесите каталог резервной копии; восстановите его `.env.selectel` в корень проекта с правами `600`. Это сохраняет пароли базы и аккаунтов. При замене VM обновите A-запись домена.
3. Выполните:

```bash
sudo docker pull postgres:17.11-bookworm
sudo python3 scripts/selectel.py restore --backup /PATH/TO/BACKUP
sudo python3 scripts/selectel.py up
sudo python3 scripts/selectel.py check
```

Восстановление проверяет контрольные суммы и отказывается перезаписывать уже существующие тома. Не запускайте `init` с новыми паролями поверх резервной копии и не удаляйте тома при обычном перезапуске. Для отката к прежнему коду используйте сохранённую ревизию; откат после несовместимого изменения схемы выполняется восстановлением резервной копии в новое окружение.

## Проверки этой поставки

Проверяются объединение Compose, наличие всех сервисов, публикация только TLS edge, независимость секретов, повторная инициализация, защита восстановления, серверный HTTPS Origin и защищённые cookie.

[Отчёт локальной проверки](../../reports/selectel/validation.json): все образы собраны, пройдены серверные тесты и браузерный вход А/Б через HTTPS, резервная копия восстановлена в отдельную базу. Для TLS-проверки использовался локальный тестовый сертификат; живой запуск на VM Selectel и запросы к LLM этим отчётом не подтверждаются.

Команды для повторения:

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
./backend/mvnw -B -ntp -f backend/pom.xml verify
```

Фактический выпуск сертификата на публичный домен и первое скачивание весов зависят от DNS и доступа к сети; скорость LLM — от CPU и доступной памяти. Развёртывание непосредственно в аккаунте Selectel выполняется после создания VM и настройки её домена.
