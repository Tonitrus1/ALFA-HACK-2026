# E5 → CatBoost: интеграция и исправления после валидации

22.10.2026, macOS arm64, CPU, Python 3.12.13. Ветка `ml/feed-recommendations`; исходный коммит `0608229bdf418ac5c22428f884013685e8a51b26`.

## Связка моделей

Профиль преобразуется в E5 query; близость query к embeddings карточек поступает в общий `FeatureBuilder` вместе с профилем, метаданными карточки и предшествующими агрегатами реакций. CatBoostRanker/PairLogit выдаёт финальные оценки, после которых применяется общий контроль разнообразия тем. Повторные ручные поправки не добавляются.

В модели уже была реализована эта последовательность. В интеграционной поставке добавлены единая команда запуска и отдельный тест фактического вызова E5 encoder и CatBoost predict через стандартную фабрику API:

```sh
./scripts/feed serve-hybrid
```

Требуется собственный `ML_INTERNAL_TOKEN` длиной от 16 символов и готовый `.local/feed-catboost`. Для другого обученного bundle: `FEED_BUNDLE=.local/run-01/catboost ./scripts/feed serve-hybrid`.

Обычная команда `serve` сохраняет E5 по умолчанию. Экспериментальная связка выбирается явно. Bundle содержит E5 и CatBoost и проверяет их контрольные суммы и совместимость. Большие веса и полные датасеты хранятся вне Git; подготовка и обучение описаны в [руководстве](../../docs/ml/feed/hackathon.md).

## Исправления валидации данных

- Все записи requests/issued/events теперь проверяются по `analytics.schema.json` перед воспроизведением истории. Недостающие/дополнительные поля, неверные диапазоны, неконечные значения видимости и некорректные timestamps отклоняются. Проверка date-time закреплена зависимостью `rfc3339-validator`.
- Схема требует для VIEW долю видимости 0,5–1 и длительность от 1000 мс; для остальных событий поля видимости равны нулю.
- Уникальность `clientEventId` проверяется по `(subjectId, companyId, clientEventId)`, как предусмотрено контрактом. Совпадающие ID разных контекстов допускаются; дубли внутри контекста отклоняются.
- Добавлены регрессионные проверки этих случаев. FeatureBuilder и веса модели не изменялись; повторное обучение из-за исправлений валидатора не требуется, полный исходный набор прошёл новые проверки.

- Полный набор: **89 тестов**, включая реальные локальные E5 и CatBoost, без ошибок; одно предупреждение deprecated alias в Starlette. [JUnit](tests.xml).
- Валидация полного набора с новыми проверками: **5000 контекстов, 40 000 запросов, 324 375 событий**, разбиение 3500/750/750. [Результат](data-validation.json).
- Реальный loopback HTTP запуск именно `./scripts/feed serve-hybrid`, без заданных `FEED_RANKER`/`FEED_BUNDLE`: readiness успешен, API использует `feed-catboost-v1-07a8233cfc32`, возвращает 72 кандидата в режиме MODEL, пустой профиль получает RULES. Тестовый сервер завершён после проверки. [Результат](command-http.json).

Контракт FEED API не изменился. Чистая установка на Linux и удалённое выполнение GitHub Actions локально не проверялись. Исходные измерения качества и производительности сохранены в [историческом отчёте](../hackathon/README.md). Исправления не являются новой оценкой пользовательской пользы: модель обучена на синтетике, независимая человеческая проверка остаётся необходимой.
