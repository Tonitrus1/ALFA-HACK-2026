## Сценарии приёмки

1. **Основной путь:** создание, финансовая форма/подтверждение, отправка, APPROVED, оферта, ACCEPTED, COMPLETED.
2. **Уточнение:** NEEDS_INFO, финансовый черновик ответа, подтверждение новой версии, повторное рассмотрение.
3. **Другие результаты:** ALTERNATIVE с допустимой суммой, DECLINED по demo-policy, MANUAL при недостатке данных/отказе Risk.
4. **Безопасность:** чужая компания/заявка/документ, CSRF, неверный Origin, старый company context и ETag, отсутствие токенов в публичном ответе.
5. **Документы:** upload → quarantine → реальный ClamAV → CLEAN → точная версия скачивания; lease/generation/source validation OCR.
6. **Лента:** изменение предпочтений, другая подборка, открытие материала, сохранение, cursor и идемпотентный replay.
7. **Надёжность:** отказ Risk/Feed, повтор команды после потери ответа, restart/recreate с теми же volumes.
8. **AI:** отдельно настоящая генерация с проверенными источниками и извлечение из синтетического изображения. Контролируемый отказ по отсутствию источников не считать успешным ответом.

Пошаговые значения и ожидаемые результаты — [demo.md](demo.md). Разрушительные/отказные сценарии исполняются на отдельном проекте, не на общем демонстрационном сервере.

## Оставшиеся ограничения

Полностью автономная CPU-сборка с Docker Ollama на целевых 8 vCPU / 16 GB и максимальная конкурентная нагрузка не подтверждены историческими отчётами. Эмбеддинги/LLM/пакеты требуют первой загрузки. Не заявляются банковская калибровка риска, production antifraud, законченный операторский MANUAL, промышленный SSO/HA и реальные интеграции. План закрытия — [bank-roadmap.md](bank-roadmap.md).
