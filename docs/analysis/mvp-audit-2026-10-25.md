## Вывод

Это интегрированный демонстрационный MVP кредитного конвейера. Основной путь реализован: потребность → продукт → заявка → подтверждённые финансы → подача → рассмотрение → решение/уточнение → предложение → принятие → демооформление. Полное соответствие комплекту требований и работоспособность всех дополнительных функций утверждать нельзя.

## Связи компонентов

1. Gateway отдаёт React и проксирует `/api/`, `/demo/api/` в backend.
2. Backend в Compose работает с `ML_MODE=http`, `ML_BASE_URL=http://ml-bridge:8000`. Bridge согласует backend DTO/digest с Risk и Feed, использует отдельную ML PostgreSQL. Risk получает Bearer token, Feed — X-Service-Token.
3. Java policy применяет бизнес-правила поверх оценки Risk. Отказ Risk переводит в MANUAL, не в автоматический отказ; Feed имеет RULES fallback.
4. OCR worker получает аренду EXTRACT у backend, читает точную CLEAN-версию, вызывает OCR API и публикует кандидатов. `total_debt` намеренно не превращается в `totalLiabilities`; недостающий показатель вводится вручную.
5. AssistantController привязывает удалённый диалог к серверной сессии и компании; контекст продуктов и заявок передаёт backend. Assistant использует SQLite, Qdrant, E5/BM25 и SearXNG.

## Существенные замечания

### 0. Подтверждённый блокер Windows checkout: CRLF в Linux-скриптах

`git ls-files --eol deploy/*.sh`: все пять файлов имеют `i/lf w/crlf`, атрибут eol не задан. `.gitattributes` не закрепляет LF для shell. Воспроизведено в собранном Linux-образе bridge: `sh /audit/feed-init.sh` → `/audit/feed-init.sh: 2: set: Illegal option -` и завершение с ошибкой. Это ломает подготовку Feed, миграции ML и запуск assistant из Windows checkout. Нужны `*.sh text eol=lf` и повторный checkout/нормализация; исходный Git blob уже LF. Для продолжения аудита созданы только временные LF-копии в `.local/audit` и override, исходники не исправлялись.

Подтверждено штатным Compose: feed-init завершился exit 2, ML PostgreSQL не смог исполнить `01-ml.sh` (`cannot execute: required file not found`). После обхода shell выяснилось, что `ml/scoring/features.py` и текстовые артефакты baseline также преобразованы в CRLF. Risk отказался запускаться с `Feature code digest mismatch`. Временное монтирование точных Git blob для scoring и model bundles устранило эту ошибку, Risk стал healthy. Защита контрольных сумм сохранена. Для исправления поставки нужно сохранять LF/точные байты также для hash-pinned кода и текстовых модельных артефактов; одной настройки shell недостаточно.

### 1. Полная AI-поставка зависит от внешнего API

`compose.yaml`, `scripts/integration/configure.py`, `ml/assistant/src/alfa_assistant/config.py`: default endpoint AITUNNEL, ключ отсутствует в генерируемой конфигурации. README прямо сообщает: без ключа OCR/assistant readiness 503, общий `compose up --wait` не проходит. OCR worker проверяет readiness до получения задания, поэтому без LLM извлечение финансов не начинается. Само наличие OpenAI-compatible API не доказывает идентичность/ревизию открытых весов провайдера.

Для сдачи следует выделить бесплатный основной профиль с корректной готовностью и явными недоступными AI-функциями либо поставить бесплатный локальный inference открытой модели. ТЗ не требует ИИ, поэтому отсутствие AI не перечёркивает основной MVP, если состав сдаваемой версии явно ограничен.

### 2. MANUAL остаётся незавершённой веткой процесса

`ReviewWorker.record` переводит дело в MANUAL и закрывает задачу; доступные обработчики возвращают в REVIEW только из NEEDS_INFO. API/кабинет оператора и завершение MANUAL не найдены. UI обещает проверку специалистом, но автоматическое обновление статуса предусмотрено только для SUBMITTED/REVIEW. После сбоя Risk заявка сама не переоценивается после восстановления.

Для ограниченного демонстрационного MVP это допустимое объявленное ограничение. Для обещания завершённой ручной обработки нужны операторская команда/симулятор и проверка MANUAL → результат.

### 3. Комплект сдачи не полностью согласован с runtime

`docs/architecture/THIRD_PARTY_NOTICES.md` посвящён архитектурным материалам и отсылает к будущему реестру приложения. Notices OCR/assistant есть, но общего актуального реестра backend/frontend/ML/контейнеров/моделей/данных/симуляторов не найдено. Часть архитектурных документов хранит старые gates и утверждение об обязательности четырёх ML-функций, которого нет в PDF. Нужна явная маркировка исторической/целевой архитектуры и фактической поставки.

### 4. Воспроизводимость сборки частичная

Frontend использует package-lock/npm ci, основные Python зависимости закреплены; OCR/assistant имеют uv.lock. Однако общие Dockerfile устанавливают Python-пакеты через pip из requirements/pyproject, а не frozen lock, и большинство базовых образов закреплены тегами без digest. Транзитивные зависимости и системные пакеты могут изменяться. Это риск воспроизводимости; само по себе не означает, что сборка сейчас сломана.

### 5. Локальная браузерная проверка настроена под macOS

`frontend/playwright.integrated.config.ts`: при отсутствии CI executablePath жёстко указывает `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`. Документированная команда test:e2e без дополнительных настроек не переносима на Windows/Linux. В Linux CI используется управляемый Chromium.

### 6. Уведомления не подключены

`frontend/src/shared/api/client.ts`: notices/readNotice возвращают unsupported/503, при этом экран Inbox существует. Основной путь опирается на историю/статус и RFI внутри приложения; самостоятельный центр уведомлений пока не готов.

## Что подтверждено прежними материалами, а не новым запуском

`reports/all-branches/linux-validation.json` заявляет PASS_WITH_EXPLICIT_LLM_BLOCKER для Linux amd64: четыре браузерных сценария, Risk/E5, ClamAV, изоляция компаний, restart/recreate, fallback, локальные RAG/Tesseract. Это сохранённый отчёт репозитория, не заново выполненные здесь проверки и не независимая верификация удалённого Actions run.

Проверено локально: Git tree hashes backend, frontend, ml, deploy, scripts и compose.yaml совпадают с runtimeTrees в этом отчёте. Это делает прежние результаты релевантными текущим исходникам, но не доказывает воспроизводимость текущего окружения или внешних зависимостей.

## Текущий локальный запуск

Docker Desktop первоначально был остановлен, затем успешно запущен. Создан новый игнорируемый `.env` со случайными служебными паролями/токенами и пустым LLM_API_KEY. Исходники приложения не изменялись. Штатная команда `docker --context desktop-linux compose up --build -d --wait --wait-timeout 900 gateway` собрала образы, но завершилась ошибкой из-за CRLF. Дополнительные AI-образы также собраны, assistant-init штатного проекта падает по той же причине. Неудачный проект остановлен без удаления volumes.

Дополнительная локальная проверка JSON Schema через bundled Python не выполнена: в runtime отсутствует пакет jsonschema; это не результат проверки контрактов приложения.

Новые результаты: Compose config --quiet PASS; frontend production build PASS; frontend 46/46 unit tests PASS в образе credit-audit-ui:20261025; frontend ESLint PASS. Backend Docker build завершил Maven package BUILD SUCCESS с пропуском выполнения тестов (unit tests backend этим запуском не проверены). Docker: 12 CPU, 8 290 877 440 байт RAM, что ниже рекомендации README 12 GB.

### Запуск с временным обходом Windows-преобразований

Создан отдельный проект `credit-audit-lf`, использующий собранные образы. Override `.local/audit/lf-override.json` подключает LF shell-скрипты и точные Git blob scoring/model bundles. Это диагностический обход, а не исправленная поставка. Команда ядра с этим override завершилась успешно, gateway/backend/обе БД/ML bridge/Risk/Feed/ClamAV healthy. Адрес: http://127.0.0.1:8080.

Первая загрузка Feed-модели оборвалась с `Network is unreachable`; повторная подготовка прошла, контрольные суммы не отключались. Модель assistant и tokenizer также автоматически подготовились.

Новые фактические результаты:

- `reports/local-audit-20261025/smoke.json`: PASS — настоящий E5; cursor/feedback/saved/idempotency; публичные OpenAPI схемы; заявка с настоящим Risk → APPROVED; запрет доступа другой компании.

- Контрольный синтетический текст распознан установленным Tesseract: `REAL_TESSERACT_CPU_PASS`.
- `reports/local-audit-20261025/ai-readiness.json`: OCR engine ready, знания/Qdrant/SearXNG доступны; readiness обоих AI-сервисов 503 из-за отсутствующего LLM_API_KEY. Внешняя генерация и OCR→LLM extraction НЕ ПРОВЕРЕНЫ.

- Chromium: 4/4 интеграционных сценария PASS (25 секунд): реальный UI → backend → Risk → принятие/демооформление; RFI correction → повторное решение; предпочтения/сохранённые материалы; VIEW и повтор feedback после потерянного ответа. Попытки с внутренним origin gateway:8080 закономерно отклонялись защитой входа; защита не изменялась.

## Приоритет перед сдачей

1. P1: закрепить точные байты/LF для исполняемых скриптов, hash-pinned кода и модельных артефактов; повторить чистый Windows checkout → Docker без override.
2. P1 для полной AI-версии: обеспечить бесплатный inference открытых весов или явно выделить бесплатный основной профиль, не обещающий OCR extraction/генерацию без модели.
3. P2: определить завершение MANUAL либо честно обозначить границу демонстрации, исправив обещание работы специалиста без реализованного продолжения.
4. P2: собрать единый актуальный THIRD_PARTY_NOTICES и согласовать архитектурные документы с runtime; приложить фактическое продуктовое исследование.
5. P2: убрать macOS-only путь браузера из локального тестового запуска, использовать frozen Python locks и закреплённые образы.

Проверочный стенд оставлен работать на 127.0.0.1:8080. Управление им: `docker --context desktop-linux compose -p credit-audit-lf -f compose.yaml -f .local/audit/lf-override.json ...`. Для остановки добавить `down` без `-v`. AI-сервисы ожидаемо unhealthy без LLM-ключа; основной сценарий работает. Временный override не входит в Git и не заменяет исправление поставки.
