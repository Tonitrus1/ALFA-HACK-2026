# Передача ML команде — 21 октября 2026

Эта поставка объединяет работающие локальные Risk API и рекомендательную ленту. Рабочая модель риска остаётся `catboost-optuna-v1`; новый логрег — исследовательский кандидат, не активированный выпуск. Полный публичный backend и frontend ещё предстоит реализовать команде.

## Какую ветку брать

Исходные опубликованные ветки расходятся от `main`: `ml/local-scoring-runtime` содержит скоринг, датасет и baseline (`f14d090a956d2a9063da57a53c269237b5df6298`); `ml/feed-recommendations` содержит отдельную ленту (`829c1c09bb248f03d730f25526de3b11712370bd`). `main` пока содержит архитектурный комплект, а не объединённые ML-сервисы. Совпадение названия локальной ветки с удалённой само по себе не доказывает совпадения её содержимого.

Для совместной разработки используйте интеграционный PR, в котором находится этот документ: обе ML-истории, исправления и актуальные инструкции должны быть проверены вместе. До принятия PR можно скачать его head-ветку и закрепить точный commit SHA. После командного review и squash merge обновите `main` и создайте собственную задачу по [CONTRIBUTING](../CONTRIBUTING.md). Не переносите отдельно старую копию общих OpenAPI из одной ML-ветки поверх другой.

## Что реализовано и кому что подключать

| Компонент | Реализовано | Ответственность интегратора |
| --- | --- | --- |
| Risk API, порт 8001 | Восемь денежных полей → восемь финансовых коэффициентов → score; PostgreSQL snapshots/inferences, повторы и проверка digest | Подтверждённые финансовые снимки, общий deadline, state machine заявки, backend policy, переходы статусов |
| Feed Ranking API, порт 8002 | E5 CPU, каталог 36 карточек, ранжирование и резервные правила | Пользователь/компания, preferences, exposures, cursor, долговечные реакции, сохранённые карточки, публичный API |
| Сценарии | Настоящие локальные HTTP/PG-вызовы плюс эталон policy; примеры feed и контрактные проверки | Совместная приёмка реального UI/backend, права доступа и эксплуатационное окружение |

Браузер вызывает backend; служебные ML-токены остаются на сервере. Risk использует `Authorization: Bearer`, Feed — `X-Service-Token`. Эти заголовки различаются намеренно и описаны в runtime-схемах.

## Запуск

Скоринг: Python 3.12, PostgreSQL 17, проверенный launcher для macOS arm64. Из корня репозитория после первой установки:

```sh
./scripts/setup-ml.sh
./scripts/demo active
./scripts/demo up --offline
./scripts/demo scenarios
./scripts/demo test
```

Первая установка требует сеть и инструменты сборки; baseline уже лежит в репозитории, переобучение для запуска не нужно. Подготовленный runtime работает локально. Linux/Windows и контейнерный rollout этим launcher не проверены. Настройка собственного PostgreSQL и ручного запуска описана в [ml-integration](ml-integration.md).

Лента использует отдельную `.venv-feed`; подготовка один раз требует сеть:

```sh
./scripts/feed setup
./scripts/feed prepare --download
# Задайте собственный ML_INTERNAL_TOKEN в окружении сервиса.
./scripts/feed serve
```

E5 закреплена по revision и SHA256 в [model-lock.json](../ml/feed/model-lock.json). Большие веса остаются в `.local/feed-bundle/`, вне Git; маленький индекс, векторы карточек и manifest передаются в `ml/feed/release/`. После подготовки inference ничего не скачивает. Без реальных подготовленных весов тесты с `--with-model` должны завершаться ошибкой; проверки без этого флага могут пропускать модельные случаи.

## Модели, ограничения и policy

Risk score имеет назначение `BANKRUPTCY_PROXY / DEMONSTRATION / DEMO_RESEARCH`. Финансы и исходы обучения синтетические. В комплекте датасета также есть происхождение реальных реестровых атрибутов; они не превращают искусственную метку в наблюдаемый кредитный дефолт. Для обучения используется `training_simulation`/`simulation_splits`, а не реестр, hybrid-файл или `simulation_truth_DO_NOT_USE_AS_FEATURES`. См. [описание датасета](../datasets/ru-sme-dataset-10000/DATASET_README_RU.md).

Модель возвращает score, а решение принимает backend. Перенесите [эталон demo_policy.py](../ml/scoring/demo_policy.py) с сохранением порядка проверок, денежных единиц и закреплённых версий. Ошибка ML не означает score=0: backend применяет MANUAL по своим правилам. Текущий baseline сохраняет `synthetic-demo-policy-3` и диагностический порог `0.03504223273828764`, исторически соответствовавший 20% подходящей validation-популяции. Это не банковский норматив.

Новый путь обучения использует вложенную CV, preprocessing внутри Pipeline и подбор на train. Опубликованные ранее validation/test уже просмотрены; их нельзя выдавать за новую независимую выборку. В [отчёте продолжения обучения](scoring-training-update.md) новый логрег улучшает некоторые синтетические метрики, но строгий Recall@5% gate не пройден: нижняя граница парного интервала равна нулю. Baseline остаётся активным. Top5% — ранговая ёмкость очереди; фиксированный порог не гарантирует ровно 5% на новой популяции. Реализация такой очереди — отдельная задача backend.

Feed использует `intfloat/multilingual-e5-small` **без дообучения**. Это cosine similarity плюс явно описанные бонусы и диверсификация, с `RULES` при пустом профиле/недоступности модели. Реакции не запускают обучение. [Model card](../ml/feed/model-card.md) и [отчёт](../reports/feed-evaluation.json) описывают ограниченный набор сценариев; они не доказывают пользовательскую полезность или превосходство над альтернативными рекомендателями. Просмотр текстов карточек исполнителем не является банковским согласованием контента.

## Проверка, выпуск и откат

Активный выбор хранится в [active-bundle.json](../ml/active-bundle.json). Новое обучение создаёт отдельный каталог и не заменяет baseline, fixtures или БД:

```sh
./scripts/demo train --output ../output/new-candidate --folds 5 --repeats 3 --threads 2
./scripts/feed test --with-model
./scripts/feed evaluate
```

Кандидат допускается к переключению только с независимыми доказательствами и проверкой загрузчика/API. Исследовательский кандидат с непройденным gate не активируется. Для проверенного выпуска команда `./scripts/demo activate --bundle <каталог>` сохраняет выбор; откат — `./scripts/demo activate --bundle ml/artifacts/baseline`. Затем перезапустите выделенный сервис, получите новый bundleDigest и закрепите его на новых попытках backend; старые запросы не должны незаметно переходить на другую модель.

Готовый [evaluated candidate](../ml/artifacts/scoring-v2-351935cfd80c/) и [saved holdout/protocol/result с provenance](../ml/experiments/scoring-v2-351935cfd80c/) передаются в этом checkout. Проверка без сети и БД:

```sh
.venv/bin/python scripts/replay_scoring_evidence.py
```

Replay проверяет hashes, отсутствие пересечений и повторяет метрики/1000 парных bootstrap-итераций; ожидаются 467 подходящих событий, 113/123 найденных baseline/candidate и `qualityGatePassed=false`. Это повтор уже просмотренного эксперимента, не новый независимый тест и не обучение. Архивные `.py.txt` служат provenance и не исполняются.

Финальная независимая проверка объединённого checkout: **31 Risk-тест на baseline и 31 на candidate**, **58 Feed-тестов с настоящей offline E5**, **426 архитектурных проверок**, пять Feed-сценариев и полный replay 1000 bootstrap-итераций — PASS. HTTP/PG включает все шесть сценариев, повторы/конкурентность, restart persistence и 503 при невозможности записи. Итог и ограничения: [final-validation.md](../reports/ml-audit-20261021/final-validation.md), [машинный отчёт](../reports/ml-audit-20261021/final-validation.json). Прежние 26 Risk-тестов — [историческая исходная проверка](../reports/ml-audit-20261021/historical-risk-baseline-tests.xml); это отдельный результат до добавления regression-тестов, а не число финального прогона.

Команды выше — инструкции воспроизведения, а не свидетельство их выполнения в окружении коллеги. Актуальные machine-readable результаты и ограничения находятся в `reports/` и в описании интеграционного PR. На момент первоначальной инвентаризации GitHub Actions runs и PR отсутствовали; наличие локальных отчётов не означает CI или приёмку другим членом команды. Реальный frontend/backend ещё должен пройти совместные сценарии из [feed-integration](feed-integration.md) и [ml-integration](ml-integration.md).

В Git передаются код, согласованные контракты, проверенные примеры, происхождение данных, утверждённые небольшие артефакты и отчёты. `.env`, `.local`, виртуальные среды, БД, download-кеши и случайные результаты экспериментов остаются вне Git. Обновление общих контрактов и модельных артефактов проходит отдельный review по правилам команды.
