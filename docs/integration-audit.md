## Сравнение вариантов

| Вариант | Изменения backend | Цена/ограничение | Решение |
|---|---|---|---|
| Переписать Java DTO и клиентов под каждый native ML | Существенные | Backend начинает зависеть от каждой версии ML; потребуется согласованная переделка | Не выбран |
| ML compatibility facade + отдельные Risk/Feed | Настройка, provenance, новый публичный Feed | Один дополнительный процесс и долговечный journal | Выбран: сохраняет backend и native API |
| Перенести Python inference внутрь Java | Существенные | Повторная упаковка моделей и валидация parity | Не выбран |

Дополнительный процесс не получает бизнес-полномочий. Он выполняет техническое согласование, не создаёт независимую state machine заявки и не читает backend DB.

## Дописать / изменить / перенести

- **ML:** bridge, журнал, version pinning, входной backend-profile, DTO/auth/digest, резервный подбор, контейнеры и тесты.
- **Backend:** созданное время financial snapshot в ML-входе; публичный Feed и его долговечное пользовательское состояние; fallback при недоступности всей ML-границы.
- **Сохранено:** Java-policy, процесс заявки/RFI, native scorer и обученный baseline, E5/каталог v1, legacy evidence.
- **Перенесено:** антифрод без независимого reference, новый CatBoost Feed без отдельной release-приёмки, полный frontend, OCR/RAG и банковское оформление.
