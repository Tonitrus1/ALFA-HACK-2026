# Проверки скоринга

Актуальность: 22.10.2026. Проверена текущая локальная реализация двух моделей в ветке `ml/local-scoring-runtime`, macOS arm64, Python 3.12.13, PostgreSQL 17.5. Кредитный bundle исходного выпуска сохранён, новый fraud bundle обучен отдельно.

## Выполненные проверки

| Проверка | Доказательство | Граница |
|---|---|---|
| Unit и HTTP API обеих моделей | [ml-tests.xml](../../../reports/ml-tests.xml) | Число тестов и время — в последнем XML; требуется запущенный стенд |
| Шесть сценариев, отдельные fraud/both и fraud-failure варианты | [dual-model-scenarios.json](../../../reports/dual-model-scenarios.json) | Исполняемый образец policy, без настоящего UI/backend |
| Перезапуск и точное повторение обоих inference | [dual-model-runtime.json](../../../reports/dual-model-runtime.json) | Выделенная локальная БД |
| Реальный отказ записи каждой модели и восстановление | Тот же runtime-протокол | Искусственная блокировка таблиц собственной БД |
| Immutable fraud records, права runtime-роли | Тот же runtime-протокол | SELECT/INSERT; изменение запрещено |
| Неизменность каждого кредитного артефакта относительно Git HEAD | Тот же runtime-протокол | Включая веса и исходный порог |
| Запрет внешней сети | Тот же runtime-протокол | OS loopback-only профиль macOS |
| Порог, синтетический test и новое семейство атак | [evaluation](../../../ml/artifacts/fraud-demo-v1/evaluation.json) | Новое семейство: 0/1335 обнаружений; перенос не подтверждён |

Проверены конкурирующие точные повторы, конфликт тела/id, подмена reference, смешивание попыток и версий, будущие источники, отсутствие авторизации, отсутствие любой оценки, NaN/Infinity и общий deadline. Смена суммы оставляет обе оценки неизменными. Исправление S03 сохраняет reference и applicationId, создаёт новую попытку/финансовую версию.

## Воспроизведение

ОС/оболочка: macOS arm64, POSIX shell; рабочий каталог: корень репозитория. Сначала setup и миграции, затем запущенный сервис. Тесты добавляют синтетические записи; runtime verifier перезапускает выделенный стенд и моделирует отказ записи.

```sh
./scripts/demo test
./scripts/demo scenarios
PYTHONPATH=ml .venv/bin/python scripts/verify_dual_runtime.py
```

## Ограничения

Использованы существующие установленные зависимости и PostgreSQL; новая установка с нуля не проверялась. Docker/Linux/Windows, backup/restore и настоящий frontend/backend E2E не проверены. Синтетические метрики не подтверждают пригодность реального банковского скоринга или антифрода. Все строки имеют одну дату оценки: out-of-time проверка невозможна.

Исторические `reports/evaluation.json`, `reports/ml-scenarios.json`, `reports/ml-runtime.json` и `reports/documentation-check-20261022.json` относятся к исходному выпуску/оформлению. Они не доказывают качество новой fraud-модели. Текущий `reports/ml-tests.xml` обновлён новым прогоном. Полная актуальная спецификация — [две модели и политика](dual-model.md).
