# Обслуживание скоринга

Актуальное дополнение от 22.10.2026: [две модели, политика, API и результаты проверки](dual-model.md). Ниже сохранено описание исходного кредитного компонента; утверждения об одной модели и отсутствии новых запусков относятся к историческому снимку до этого дополнения.

Назначение: обслуживание скоринга.

Статус реализации: отдельный локальный ML-сервис; публичный backend и frontend не поставляются. Статус проверки документации — в [verification.md](verification.md).

Актуальность: 22.10.2026. Исходный проверяемый снимок: `ml/local-scoring-runtime` / [`f14d090a956d`](https://github.com/Tonitrus1/ALFA-HACK-2026/commit/f14d090a956d2a9063da57a53c269237b5df6298). Среда исторических runtime-проверок: macOS arm64, Python 3.12.13. При этой миграции сервисы повторно не запускались.

## Start, stop и готовность

Подготовка описана в [setup](setup.md). Runtime локальный, без платных запросов. Start запускает выделенные ML/БД; down останавливает только процессы, заданные локальным launcher и маркером проекта.

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
./scripts/demo up --offline
```

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
./scripts/demo down
```

Готовность — авторизованный `/health` по [команде setup](setup.md#проверка-готовности), HTTP 200/ready=true. Ожидаемый результат down — завершение ML и выделенного PostgreSQL; inference records сохраняются.

## Сохраняемое и временное состояние

`.local/pgdata` — долговечные feature/inference, `.local/runtime.json` — секреты, `.local/*.pid`/логи — локальное управление. `ml/artifacts/baseline` — закреплённая модель; `ml/generated`/fixtures/reports — результаты подготовки. Не переносите pgdata в другой каталог с подменой guard-маркеров.

## Обновление модели

Следующая команда изменяет bundle, policy, selection-lock, synthetic fixtures/generated и отчёты. Это обучение, не обычный start; на работающей общей поставке её не выполнять. Сеть для обучения не нужна.

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
./scripts/demo train --trials 30 --folds 3 --threads 4 --shortlist 5
```

Ожидается новый manifest/evaluation/study и проверяемые hashes. Опциональный `--dataset`/DATASET_PATH выбирает другой локальный набор; `--storage` задаёт локальную Optuna БД, это не registry активной модели. Не выдавайте сохранённый study за пройденный release gate.

## Миграции и восстановление

Миграции относятся только к ML-схеме. Команда ниже создаёт/использует выделенную БД и изменяет её схему; применённый SQL проверяется по digest, менять его задним числом нельзя.

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
./scripts/demo migrate
```

Индексы — PostgreSQL, отдельного векторного индекса нет. Восстановление из резервной копии не автоматизировано и не проверялось этой документационной работой.

## Переключение выпуска и откат

В этом снимке launcher фиксирует `ml/artifacts/baseline`; нет active pointer, activate CLI и автоматического rollback. Для изменения поставки сначала остановить ML, подготовить и проверить согласованный bundle в отдельной копии, затем развернуть его и заново проверить health/сценарии. Ручной server поддерживает MODEL_BUNDLE, но launcher его переопределяет. Проверенный протокол production-переключения не поставляется; команды кандидатов интеграционной ветки сюда не копируются.

## Логи и диагностика

`.local/ml.log`, `.local/postgres.log`; не публиковать их без проверки на секреты/DSN. Ошибки manifests/версий не обходить. Для 403 проверить токен, для 409 — IDs/digest, для 422 — формат; timeout/ошибка сохранения требуют MANUAL в backend. [Исторические проверки](verification.md).

## Backup, restore и reset

Готового backup/restore CLI нет; восстановление не подтверждено. Не копируйте работающий pgdata как гарантированную резервную копию. Сохранение секретов и bundle вместе с согласованной резервной копией — ответственность deployment.

Следующая операция удаляет **все synthetic feature/inference записи выделенного стенда** и останавливает сервис; не относится к пользовательской БД. Guard проверяет имя/адрес/маркер/владельца. Bundle, fixtures и датасет остаются. Выполнять только для намеренного сброса демонстрации.

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
./scripts/demo reset --confirm credit_scoring_demo
./scripts/demo up --offline
```

Ожидается сообщение об очистке `ml.features` и `ml.inferences`; новые запросы создают новые IDs. Исторический reset не означает backup/restore.
