# Обучаемая рекомендательная лента: поставка для хакатона

22.10.2026. Реализованы ML-компоненты; backend, авторизация, БД и UI в поставку не входят.

Сервис поддерживает E5 и CatBoostRanker поверх E5-признака. В текущей поставке по умолчанию работает E5: независимая человеческая проверка контента и разметки ещё не выполнена. CatBoost можно явно выбрать для демонстрации.

## Что поставлено

- Каталог v2: 72 карточки, 6 тем × 3 глубины × 4 материала. Исходные 36 карточек не изменены. Новые 36 дают по одному примеру каждой отрасли в каждой теме. Пустые отраслевые теги означают универсальный материал; отрасль не ограничивает eligibility.
- Каталог v1, его иллюстрации и review: `ml/feed/catalog/versions/v1/`. Прежние release metadata и embeddings: `ml/feed/releases/v1/`. Это позволяет воспроизводить прежнюю версию с закреплёнными весами E5.
- Детерминированный симулятор, проверка воспроизведения истории, общий расчёт признаков, четыре конфигурации CatBoost/PairLogit, сравнение пяти алгоритмов, два стресс-сценария, HTTP smoke и демонстрационный сценарий.
- Строгий контракт аналитического экспорта и пример для backend-команды.
- Минимальный Linux CI; выполнение GitHub Actions и обязательность checks в настройках репозитория локально не подтверждены.

## Подготовка и воспроизведение

Из корня репозитория, Python 3.12:

```sh
./scripts/feed setup
./scripts/feed prepare --download
./scripts/feed pipeline \
  --work .local/reproduction-01 \
  --reports reports/reproduction-01 \
  --model-source .local/feed-bundle/model
```

`--download` — явное разрешение скачивания закреплённых модельных файлов при подготовке. Все последующие шаги используют локальные веса. Если они уже есть, подготовьте bundle без сети:

```sh
./scripts/feed prepare --model-source /absolute/path/to/verified-e5/model
```

Единая команда не перезаписывает имеющиеся каталоги запуска. Для быстрой проверки можно добавить `--users 100 --skip-http`; полноценный запуск использует 5000 контекстов, 200 HTTP запросов и два отдельных стресс-набора по 500 контекстов. `--skip-http` не подтверждает HTTP SLO.

Для уже подготовленной текущей поставки команды по этапам:

```sh
./scripts/feed simulate --output .local/new-synthetic-data
./scripts/feed validate-data --data .local/new-synthetic-data
./scripts/feed train --data .local/new-synthetic-data --output .local/new-catboost
./scripts/feed benchmark --data .local/new-synthetic-data --bundle .local/new-catboost --output reports/new-benchmark.json
./scripts/feed smoke --bundle .local/new-catboost --output reports/new-http-load.json
./scripts/feed demo --bundle .local/new-catboost --output reports/new-demo.json
./scripts/feed test --with-model --with-learned
```

Веса и полные датасеты находятся в игнорируемой `.local/`. Они намеренно не включаются в Git. Локальная среда этой проверки использовала уже установленные пакеты; чистая установка воспроизводится через `setup` и закреплённый список зависимостей. Чистая установка на Linux здесь не запускалась.

## Выбор модели и API

Обычный E5:

```sh
export FEED_RANKER=e5
export FEED_BUNDLE=.local/feed-bundle
./scripts/feed serve
```

Экспериментальная связка E5 → CatBoost, одна команда:

```sh
./scripts/feed serve-hybrid
```

Команда устанавливает `FEED_RANKER=catboost`; bundle по умолчанию — `.local/feed-catboost`, содержащий E5 и CatBoost. Можно указать другой обученный bundle: `FEED_BUNDLE=.local/reproduction-01/catboost ./scripts/feed serve-hybrid`.

Эквивалентный запуск с явными переменными:

```sh
export FEED_RANKER=catboost
export FEED_BUNDLE=.local/feed-catboost
./scripts/feed serve
```

Перед запуском задайте собственный `ML_INTERNAL_TOKEN` длиной от 16 символов. Браузер не должен знать этот токен.

`POST /internal/v2/rankings`, запрос, ответ, токен, Idempotency-Key и предел 100 кандидатов не изменились. `mode=MODEL` используется для обеих моделей; `releaseId` различает реализацию и bundle. Пустой профиль по-прежнему получает RULES даже при отказе модели. При недоступности выбранной модели — 503/RULES; backend сохраняет существующий fallback. Неизвестный `FEED_RANKER` вызывает ошибку конфигурации.

CatBoost использует E5 similarity, совпадения метаданных, профиль и предшествующие агрегаты реакций. ID, позиция, будущие события и скрытые параметры симулятора в признаки не входят. Одинаковый `FeatureBuilder` обслуживает train и API. Ручные бонусы после CatBoost повторно не прибавляются; финальное разнообразие тем сохраняется. Explanations остаются объяснениями соответствия профилю и не являются точным вкладом признаков CatBoost.

## Данные и границы выводов

Базовый набор: 5000 отдельных вымышленных пар user/company, четыре сессии и до двух порций по шесть. Получены 40000 запросов, 240000 записей выданных карточек и 324375 событий. Разбиение до генерации историй: 3500/750/750 контекстов. Все записи помечены `isSynthetic=true`; реальные компании, их идентификаторы, финансовые суммы и метки скоринга не используются.

`requests.parquet` хранит снимок состояния до выдачи; `issued.parquet` — позиции и фактически выданные элементы; `events.parquet` — принятые события. `private/truth.parquet` доступен только оценке. Обучение проверяет hashes трёх наблюдаемых файлов и не открывает truth. Отсутствие или повреждение private truth не препятствует обучению.

Вероятностная полезность зависит от отдельных скрытых тематических предпочтений, глубины и формата; конфигурация содержит связь намерений с распределением интересов. E5 и RulesRanker не вычисляют награды. Случайная выдача используется в 70% порций, правила — в 30%. Позиция и усталость влияют на вероятность VIEW. Изменение реакции заменяет состояние, а повтор события не увеличивает счётчики.

Метки PairLogit: последняя HELPFUL=2, CLICK без явной реакции=1, последняя NOT_INTERESTED=0. VIEW без дальнейшего действия и непоказанные карточки исключаются. Группа — exposure; остаются только группы с двумя наблюдаемыми карточками и разными метками. В полном train осталось 17028 групп/54319 строк, validation — 3599/11505. Отбор конфигурации использует только validation; test-метрики вычисляются после сохранения модели.

Симуляция не устраняет selection/position bias и не доказывает пользовательскую пользу. Истинная полезность генератора не считается реальной разметкой. Доли действий и отраслей являются параметрами сценария, а не статистикой пользователей банка.

## Оценка и выпуск

Сравниваются случайный порядок, Rules, E5, E5+поправки и CatBoost. На одинаковых полных наборах кандидатов считаются NDCG@3/6, Recall@6, покрытие и разнообразие до/после общей диверсификации. Для пустого профиля все варианты используют действующий RULES fallback. Recall использует известную полную разметку; отсутствие события не означает отрицательную релевантность. Ожидаемая доля NOT_INTERESTED рассчитывается внутри симулятора и не называется измеренным online outcome.

95% интервал разницы строится bootstrap по пользовательским контекстам. Срезы: отрасль, глубина, задача, наличие профиля и истории. Стресс-наборы усиливают влияние позиции или ослабляют связь профиля с интересами; модель для них не переобучается.

`ml/feed/fixtures/content-review.json` содержит 24 профиля и полную черновую разметку 72 карточек, 12 development/12 test. Это AI_DRAFT с общей редакционной рубрикой, не независимый экспертный benchmark. Человек должен проверить каждую оценку, зафиксировать test до следующих итераций, указать reviewer и сменить reviewKind на HUMAN_REVIEW. Идентичные профили разных частей запрещены; закрытые профили не используются для выбора конфигурации.

Критерии качества: относительный прирост NDCG@6 ≥3%, положительная нижняя граница интервала, прохождение пяти сценариев, отсутствие падения содержательной NDCG@6 больше 0,02. Отдельно обязательны успешные контрактные/runtime тесты и HTTP smoke. Отчёт benchmark оценивает качество и человеческую проверку; он сам не переключает сервис. Конфигурация по умолчанию остаётся E5, эксперимент выбирается явно.

Bundle проверяет model/report hashes, признаки, версии CatBoost и каталога, связь с E5 manifest. Training report содержит параметры, все четыре запуска, лучший результат validation и feature importance. Feature importance не является индивидуальным объяснением карточки. Для rollback верните FEED_RANKER=e5 и соответствующий FEED_BUNDLE. Исторический каталог v1 требует согласованного старого каталога на backend и ML; простой смены весов для него недостаточно.

## Проверки и оставшаяся работа

Локальные отчёты: `reports/hackathon/`. Исторические отчёты вне этой папки сохранены как свидетельства предыдущей версии. Их нельзя переносить на новую модель.

Нужны действия команды: человеческая проверка новых текстов и 24 профилей, подключение долговечного backend-хранилища и UI, затем реальная оценка. В этой поставке не реализованы эти компоненты, настоящий A/B, feature store, ANN, fine-tuning E5, Kubernetes и автоматическое переобучение.
