# Обслуживание рекомендательной ленты

> Обновление 22.10.2026: каталог v2 на 72 карточки, синтетические события и экспериментальный CatBoost описаны в [текущей поставке](hackathon.md). Разделы ниже сохраняют описание E5 MVP и исторические проверки; новые результаты находятся в `reports/hackathon/`. [Контракт аналитического экспорта](analytics-contract.md).

Назначение: обслуживание рекомендательной ленты.

Статус реализации: отдельный локальный ML-сервис; публичный backend и frontend не поставляются. Статус проверки документации — в [verification.md](verification.md).

Актуальность: 22.10.2026. Исходный проверяемый снимок: `ml/feed-recommendations` / [`829c1c09bb24`](https://github.com/Tonitrus1/ALFA-HACK-2026/commit/829c1c09bb248f03d730f25526de3b11712370bd). Среда исторических runtime-проверок: macOS arm64, Python 3.12.13. При этой миграции сервисы повторно не запускались.

## Start, stop и готовность

В подготовленной среде с собственным токеном:

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
./scripts/feed serve
```

Ожидается foreground uvicorn на 8002. Остановка — Ctrl+C в том же терминале, без поиска и завершения чужих процессов. Отдельной команды `scripts/feed stop` нет. Авторизованный `/health`: [setup](setup.md#проверка-готовности). HTTP200/ready=true обязателен; сам живой процесс при ошибке bundle может отвечать 503.

## Сохраняемое и временное состояние

Runtime bundle `.local/feed-bundle` файловый; Python environment `.venv-feed`; векторы/manifest производны от каталога. Токен задаётся внешне, самим сервисом не сохраняется. Пользовательская БД в ML отсутствует; in-memory reference projection не использовать как production state. После restart пользовательские данные восстанавливает backend из собственного хранилища.

## Обновление модели и каталога

Увеличить version изменённых карточек и catalogVersion, выполнить новый содержательный review; это не автоматическое банковское согласование. Затем команда ниже пересчитает локальные embeddings и manifest. Без `--download` она не обращается к upstream за недостающими файлами.

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
./scripts/feed prepare
```

Ожидается matching manifest/catalog index и новые hashes. После изменения upstream revision требуется явное обновление model-lock и hashes отдельным review; не меняйте закреплённый model.safetensors без версии. Примеры и проверка выполняются отдельно, это запись файлов/отчётов:

ОС/оболочка: macOS arm64, POSIX shell. Рабочий каталог: корень соответствующей ветки репозитория.

```sh
.venv-feed/bin/python -m ml.feed.export_examples
./scripts/feed test --with-model
./scripts/feed evaluate
```

Evaluation по умолчанию обновляет `reports/feed-evaluation.json`; примеры — `ml/feed/examples`. Не заменять исторический evidence новым PASS без фактического прогона.

## Миграции и восстановление индексов

SQL-миграций у FEED нет. Индекс — локальные embeddings; восстанавливается подготовкой из закреплённых каталога/model-lock. При несовпадении manifest/hashes runtime не должен использовать частичный комплект. Миграции профилей/реакций/cursors принадлежат backend, не этой службе.

## Переключение выпуска и откат

FEED_BUNDLE выбирает полный каталог. Для ручного switching остановить foreground, сохранить согласованный старый bundle, подготовить новый отдельно, задать путь и проверить health/контракты. Hot reload/атомарный rollout/автоматический rollback не реализованы и не проверены. Многопроцессный worker deployment загружает собственные веса на каждый процесс; для MVP исторически использовался один.

Для отката нужны совпадающие каталог/версии/SVG у backend и ML; смена одной модели без состояния backend небезопасна для cursor/exposure. Проверенный инструмент production rollback не поставляется.

## Логи и диагностика

Логи uvicorn идут в терминал; штатного persistent log-path нет. Logger сообщает ошибку загрузки/inference без полного payload. Не журналировать токены и пользовательские профили. При timeout/503 backend использует RULES; при 403/409/422 исправляется настройка или контракт. [Ошибки](integration.md#ошибки-timeout-retry-идемпотентность-и-fallback).

## Backup, restore и reset

Готового backup/restore/reset CLI нет, процедуры восстановления пользовательского состояния неприменимы к ML. Для offline-переноса сохраняйте весь проверенный bundle и зависимости. Применение backup/restore backend-БД отдельно не проверялось. Не переносите reset-команду рисковика в FEED и не удаляйте каталог ради сброса реакций: реакции принадлежат backend.
