# Продолжение обучения скоринга — 21 октября 2026

Обучен кандидат **scoring-v2-351935cfd80c**: логистическая регрессия C=0.1 без балансировки. Заполнение отсутствующих отношений и масштабирование сериализованы внутри Pipeline. Сервис принимает прежние восемь денежных полей, рассчитывает прежние восемь отношений и возвращает тот же RiskResult со score от 0 до 1.

## Новая независимая синтетическая проверка

До генерации и оценки закреплены модель, seed=2026102105, объём 20 000, исходная формула генератора и критерии. Новые финансовые векторы и вымышленные ID не пересекаются с исходными 10 000. Финансы созданы неизменённой исходной функцией; использован фиксированный исходный intercept, без калибровки на holdout. Категории МСП взяты из распределения реального реестра; реальные компании не получают искусственные оценки дефолта.

В подходящей финансовой группе **16284 компаний, 467 искусственных событий**. Сравнение моделей на одних наблюдениях, одинаковая ёмкость rank-очереди:

| Показатель | Рабочий CatBoost | Новый логрег |
| --- | --- | --- |
| Проверено компаний, не более 5% | 814 | 814 |
| Найдено событий | 113 | 123 |
| Precision@5% | 13.88% | 15.11% |
| Recall@5% | 24.20% | 26.34% |
| AP | 0.13856 | 0.15067 |
| Обычный Logloss | 0.11241 | 0.11024 |
| Brier | 0.02630 | 0.02610 |

Разница Recall +2.14 п.п.; парный 95% bootstrap-интервал **[0.00; 4.61] п.п.**. Кандидат выглядит перспективно и улучшает вероятностную ошибку, но заранее заданный строгий критерий нижней границы Recall >0 не выполнен. Нельзя объявлять доказанную победу по числу найденных событий. Семя, данные и критерии после оценки не подбирались; повторный поиск на этой выборке не запускался.

**Рабочая модель не заменена.** Статус кандидата — evaluated-candidate; автоматическая активация блокируется. Активный пакет — `ml/artifacts/baseline`, версия catboost-optuna-v1. Это честное продолжение разработки, а не обещание реального кредитного качества.

Для нового кандидата фиксированный OOF-порог равен 0.09265521. На новой группе он направляет на проверку 881 компаний (5.41%). Поэтому оценка top5% и применение фиксированного порога различаются: точные 5% требуют очереди в backend. В рабочем baseline сохранена старая policy-3/20%; экспериментальная policy-4/5% ещё не активирована.

## Что исправлено в обучении

- Validation и прежний test больше не участвуют в подборе. Новое обучение читает только train; проверенная в этом продолжении новая выборка используется один раз для подтверждения.
- Повторная внешняя CV 3×5 и внутренние 3 фолда; все сравнения используют одинаковые разбиения. Метрика подбора соответствует целевым 5% финансово подходящих компаний.
- Константа, логрег, Balanced-логрег и умеренный CatBoost сравниваются явно. Диагностический Balanced не может автоматически победить и не используется как некалиброванная PD.
- Масштабирование и imputation обучаются только внутри train-части фолда. Preprocessing путешествует вместе с моделью.
- Ограниченный заранее заданный поиск заменяет широкую Optuna и shortlist по validation. Фиксированное число деревьев не выбирается по внешнему фолду; неподтверждённая калибровка не добавляется.
- Сохраняются конфигурации, версии, SHA, состав фолдов, OOF и все метрики @5/10/20% на общей и подходящей популяциях. Независимая проверка содержит парную неопределённость фиксированных моделей.
- Обучение создаёт новый каталог кандидата, не перезаписывает baseline, fixtures, generated, reports и не обращается к БД. Учебные исходы по-прежнему обозначены как синтетический прокси банкротства; они не объявлены реальным кредитным дефолтом.

Расширенные 36 финансовых/реестровых признаков остались в отдельном демо-эксперименте предыдущего аудита: убедительной пользы не показали. Они не сделаны обязательными входами сервиса. Для их будущего внедрения потребовался бы согласованный источник обогащения, а не скрытая подмена восьми полей API.

## Совместимость и будущая интеграция

- `features.py`, runtime OpenAPI, архитектурные контракты, зависимости, миграции, старые веса, policy и сценарии сохранены. Проверены контрольные суммы 85 защищённых файлов.
- Новый загрузчик поддерживает CatBoost и sklearn Pipeline через единый интерфейс вероятностей; проверяет версию схемы, порядок восьми признаков, библиотечные версии, hashes и классы [0,1].
- Прежний baseline сохраняет точные прогнозы. Кандидат и baseline прошли реальные HTTP/PG-проверки на отдельных портах; рабочее соединение на 8001 не переключалось.
- 26 тестов последнего прогона кандидата: запросы, ответы, JSON Schema, concurrent retries, идемпотентность, конфликты, authentication, нулевые знаменатели, невалидные деньги, плохие артефакты, отказ активации, публикация и откат. Шесть сценариев APPROVED/DECLINED/NEEDS_INFO/ALTERNATIVE/MANUAL проходят.
- После перезапуска повтор запроса возвращает те же snapshot/inference/score; при недоступной записи результат не выдаётся, API отвечает 503. Проходят и логрег, и прежний CatBoost.
- Решение о выдаче кредита остаётся backend policy. Модель возвращает риск; frontend показывает статус из backend. Новых обязательных полей для интеграции не появилось.
- Выбор пакета закреплён в `ml/active-bundle.json`. Проверенный выпуск публикуется отдельной неизменяемой папкой; откат указывает на baseline. Будущий commit включает и указатель, и весь bundle.
- При смене выпуска backend должен получить новый bundleDigest для новых попыток. Старые закреплённые запросы получают предусмотренный 409; одновременный роутинг разных model bundles в одном процессе здесь не добавлен.

## Воспроизводимая передача команде

- `ml/artifacts/scoring-v2-351935cfd80c/`: точный evaluated-candidate с исходными SHA256, OOF, параметрами, policy, fixtures и закреплёнными отчётами. Пакет не переобучен и не изменён при переносе.
- `ml/experiments/scoring-v2-351935cfd80c/`: сохранённые `independent_holdout.parquet`, `independent_protocol.json`, `independent_result.json`, provenance и SHA256SUMS.
- `archive/*.txt` внутри evidence — только архив исходников генератора и обучения; replay/runtime их не импортируют. Архивные train/learning совпадают с hashes исходного protocol; текущий train дополнительно защищает всё дерево публикаций.
- `scripts/replay_scoring_evidence.py`: переносимая проверка сохранённого результата без внешних путей, БД, обучения или генерации данных.

Из корня checkout после установки закреплённых зависимостей `./scripts/setup-ml.sh`:

```sh
.venv/bin/python scripts/replay_scoring_evidence.py
PYTHONPATH=ml .venv/bin/python -m pytest ml/tests/test_releases.py ml/tests/test_training_guards.py -q
./scripts/demo active
```

Replay проверяет checksums evidence/моделей/исходного датасета, уникальность и отсутствие пересечений ID и финансовых векторов, пересчитывает все сохранённые метрики и 1000 парных bootstrap-повторов с исходным seed. Ожидается 16284 eligible / 467 событий, 113/123 найденных событий и `qualityGatePassed=false`. Это повторное воспроизведение **уже выполненной** независимой оценки, а не новая независимая проверка. Оно не активирует кандидат и не подтверждает побитовое переобучение. Подробности — в README evidence-каталога.

Текущий `train.py` запрещает новый output внутри всего `ml/artifacts/`, над ним и через symlink, до чтения датасета; обычный новый offline-каталог допустим. Для policy с boundary tie при p=1, который нельзя исключить с порогом в [0,1], выдаётся понятный ValueError: недопустимый пакет не создаётся. При достижимом пороге сохраняется `>=` и исключение целого tie без превышения целевых 5%.

Для обучения следующего кандидата: `./scripts/demo train --output ../output/new-candidate --folds 5 --repeats 3 --threads 2`. Не донастраивать этот кандидат по сохранённой проверке: она уже просмотрена. Для реального качества необходимы наблюдаемые дефолты; для следующего синтетического исследования — новый заранее описанный сценарий и независимое подтверждение после фиксации выбора.
