- Mock workflow: 8 — полный COMPLETED, replay и конфликт тела, CAS, подтверждения, MANUAL/DECLINED, RFI с версиями и только запрошенными полями, tenant isolation, закрытый карантинный файл.

## Браузерные проверки

Установленный Google Chrome, desktop 1440×1040 и narrow web 390×844:

1. Вход → потребность → продукт → компания → восемь подтверждённых финансов → согласие → отправка → предложение → принятие → «Демонстрация, деньги не перечисляются».
2. Вход клавиатурой, фокусируемость заголовка, помощник не обещает одобрение.
3. Upload → CLEAN/OCR READY → явная сверка восьми значений → изменение сбрасывает подтверждение → отправка → скачивание исходных байтов CLEAN-файла.
4. Смена компании изолирует заявки; возврат восстанавливает ввод; выход переводит к входу.

Эти четыре проверки прошли на обоих размерах экрана (8 запусков). Ключевой путь и клавиатура/помощник дополнительно прошли на production preview (4 запуска). Проверки фиксируют отсутствие горизонтального переполнения для кабинета/сценариев. Полный аудит WCAG и всех браузеров не выполнялся.

Отдельно на desktop прошли: `rfi`, `manual`, `declined`, `network`, `conflict`, `ocr-failed`. RFI отправляет ответ с документом в ту же заявку. Network восстанавливается после 503/Retry-After. Conflict требует явного сопоставления версий. CLEAN не подменяет OCR READY.

Скриншоты кабинета и завершения сохранены в `screenshots/`. Они сняты с production preview после окончания загрузки кабинета.

## Исправленные находки

Испытания выявили и помогли исправить устаревшее следующее действие сразу после submit, потерю наблюдателя сессии при очистке Query cache, пограничный CRLF-разбор SSE и риск второй очереди при повторном открытии формы. После форматирования долгоживущий dev-сервер один раз отдал устаревший преобразованный модуль; финальные браузерные проверки выполнены после его перезапуска, а основной путь дополнительно проверен на неизменяемом production bundle.
