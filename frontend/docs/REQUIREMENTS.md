## Сквозные требования

- React Hook Form владеет вводом; Ant Design Form не используется. TanStack Query владеет ответами API.
- Очередь на черновик: debounce, один запрос, coalescing нового ввода, flush, остановка на ошибке. Ответ не сбрасывает ввод.
- При 409/412 отображаются обе версии. Перезапись возможна только после явного выбора пользователя. Для изменившегося RFI можно загрузить актуальные требования.
- Введённые данные удерживаются в памяти по компании/ресурсу, без browser storage. Перезагрузка уничтожает mock-данные и несохранённый ввод.
- CSRF и company context из сессии, `credentials: include`, `If-Match`, ключи значимых команд и сверка операций после потери ответа.
- Только метаданные команд хранятся в sessionStorage. Там нет тела запроса, токенов, финансов и файлов.
- 401 останавливает фоновые запросы и поток; 403/404 не повторяются; 422 нормализуется; 429/503 учитывают Retry-After; файловые ошибки не показывают HTML.
- SSE через fetch: Last-Event-ID, heartbeat, reconnect с ограниченной задержкой, snapshot после разрыва, обход страниц snapshot. Dirty-form не сбрасывается событиями.
- BroadcastChannel отменяет запросы и перечитывает сессию при смене компании в другой вкладке. Реальная общая cookie-сессия проверяется только с backend; mock-хранилище изолировано по вкладкам.
- Показы продуктов учитываются при видимости ≥50% в течение ≥1 с. События только VIEW/CLICK.
- Помощник выводит обычный текст с escaping React. Активны только явно разрешённые внутренние ссылки, отмена и таймаут 65 с.
- Узкий viewport, native labels, уникальные имена финансовых подтверждений, focus заголовков, reduced motion. Полная сертификация доступности не заявляется.

## Что не подтверждено

Совместимость с исходным OpenAPI/state-machine, реальный cookie login/CSRF, durable recovery, межвкладочная серверная сессия, CPU RAG/OCR, банковские полномочия и integrated-приёмка требуют работающего backend и исходных контрактов. Текущая сборка — frontend с демонстрационными адаптерами.
