# Поток — frontend кредитного кабинета

React SPA кредитного кабинета с русским интерфейсом. По умолчанию используются искусственные данные MSW; подключение реальных банковских сервисов требует отдельной интеграции.

Материалы репозитория: [руководство frontend](../docs/architecture/packages/frontend/docs/guide.md), [публичный API](../docs/architecture/contracts/public.openapi.json), [правила команды](../CONTRIBUTING.md). В самостоятельном ZIP эти материалы доступны в GitHub-репозитории.

## Docker и публикация в Git

Добавлены Dockerfile с двухэтапной сборкой Node → Nginx, compose.yaml, healthcheck, SPA fallback и reverse proxy для API/SSE. Для запуска на компьютере с работающим Docker Desktop:

```powershell
docker compose up --build -d
```

Откройте http://localhost:8080/login. Node.js на хосте не требуется. Подробная инструкция по Docker, backend и GitHub: [docs/DOCKER-AND-GIT.md](docs/DOCKER-AND-GIT.md).

ZIP с исходниками не является готовым Docker-образом. Для передачи уже собранного образа используйте `docker save`, как описано в инструкции.

## 1. Быстрый запуск

Требуется Node.js 24 LTS и npm. В каталоге проекта:

```powershell
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. По умолчанию работает MSW-демо, подключение к backend не требуется. Если порт занят, остановите прежний сервер или задайте `npm run dev -- --port 5174`.

Проверка сборки:

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

`preview` обслуживает собранный `dist` (обычно порт 4173). Открытие index.html двойным кликом не поддерживается: SPA и Service Worker требуют HTTP/localhost. Для размещения нужен SPA fallback и один origin с API.

## 2. Переменные окружения

Скопируйте `.env.example` в `.env`. Не добавляйте токены, пароли, реальные финансовые и персональные данные в VITE_*.

| Переменная          | По умолчанию          | Смысл                                                                     |
| ------------------- | --------------------- | ------------------------------------------------------------------------- |
| VITE_API_MODE       | mock                  | mock / integrated                                                         |
| VITE_DEMO_SCENARIO  | success               | Сценарий только MSW                                                       |
| VITE_CONTRACT_ACK   | отсутствует           | Для integrated нужен `provisional-v1` после согласования временной модели |
| BACKEND_ORIGIN      | отсутствует           | Локальный Vite proxy для `/api`; например http://127.0.0.1:8080           |
| PLAYWRIGHT_BASE_URL | http://127.0.0.1:5173 | Адрес сервера для браузерных тестов                                       |
| E2E_SCENARIO        | отсутствует           | Название отдельного проверяемого демосценария                             |

После изменения VITE_* перезапустите сервер. Они фиксируются во время build.

## 3. Структура

```text
src/
  app/                 # Providers, cookie-session context, layout, routes
  features/
    access/            # Вход и выбор компании
    catalog/           # Потребность и продукты
    application/       # RHF, очередь сохранения, четыре шага заявки
    documents/         # Upload, статусы, OCR-сверка, скачивание
    journey/           # Статус и RFI
    offers/            # Принятие и демооформление
    feed/              # Кабинет, события видимости, сообщения
    assistant/         # Безопасный диалог и источники
  shared/
    api/               # HTTP, CSRF, CAS, команды, recovery, SSE
    lib/               # Деньги, проверки, очередь, демопереходы, снимок
    types/             # Явно временные DTO
    ui/                # Общие карточки, поля, статусы и состояния
  mocks/               # MSW handlers и согласованная модель демо
  styles/              # Одна система CSS, адаптивность, reduced motion
tests/                 # Unit и Playwright
docs/                  # Матрица, интеграция, результаты проверок
tools/                 # Повторяемый запуск отдельных демосценариев
public/                # MSW Service Worker
```

React 19, TypeScript strict, Vite, React Router 7, TanStack Query 5, React Hook Form 7, Zod 4, Ant Design 5, MSW 2, Lucide. Точные установленные версии зафиксированы в package-lock.json. Ant Design Form не дублирует RHF. Server state находится в Query, пользовательский ввод — в RHF.

## 4. Экраны

Реализованы U01–U16: вход, компании, кабинет, потребность, каталог, продукт, данные компании, финансы, документы/OCR/согласия, проверка, статус, ответ на RFI, предложение, сообщения, файлы, помощник. Полная таблица маршрутов и требований — в [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

Дополнительно доступны две внутренние страницы базы знаний `/help/application` и `/help/finance`, связанные с источниками помощника.

## 5. Как показать жюри

1. Откройте `/login`, оставьте демонстрационное имя, нажмите «Войти в кабинет».
2. Выберите ООО «Мастерская роста». В кабинете нажмите «Подобрать финансирование».
3. Выберите цель, сумму 3 000 000 ₽ и срок 12 месяцев. Откройте «Оборотный кредит» и создайте заявку.
4. Проверьте компанию. На шаге финансов проверьте восемь искусственных значений и отметьте каждое подтверждение.
5. По желанию загрузите искусственный TXT/PDF/PNG/JPG до 10 МБ. Дождитесь CLEAN и готового OCR, откройте сверку, сравните/отредактируйте и подтвердите восемь значений. В демо OCR синтетический и не читает содержание файла.
6. Подтвердите согласие. На проверке сверьте данные и документы, отметьте итоговое подтверждение, отправьте заявку.
7. Дождитесь результата (несколько секунд). Откройте предложение, ознакомьтесь с условиями, подтвердите принятие.
8. Завершите оформление заявки. Финальный экран: «Оформление завершено».
9. Покажите историю, сообщения, CLEAN-файлы и помощника. Вопрос об одобрении получает ответ об ограничениях, а не обещание.

Для сценария `rfi` после рассмотрения появится запрос: измените только выручку, подтвердите её и приложите искусственный документ. После CLEAN отправьте ответ. Продолжение происходит в той же заявке, без повторного создания.

По руководству внешняя приёмка должна выполняться с integrated CPU-профилем. Текущий показ подтверждает только frontend/mock-путь; integrated-приёмка ещё требует backend.

## 6. Деморежим и сценарии

MSW перехватывает тот же API-клиент, которым пользуется integrated-режим. В экранных компонентах нет переключений `if mock`. Сценарий задаётся окружением, операторской/административной панели в публичном UI нет.

```powershell
$env:VITE_DEMO_SCENARIO='rfi'
npm run dev
```

Значения:

- `success`: предложение → принятие → демонстрационное завершение.
- `rfi`: уточнение выручки и подтверждающий документ → предложение.
- `manual`: ручная проверка, явно не отказ.
- `declined`: отрицательное решение, заданное сценарием.
- `network`: первая попытка автосохранения получает 503/Retry-After; ввод остаётся, доступно повторение.
- `conflict`: первая попытка сохранения получает 412; UI показывает обе версии и требует выбора.
- `ocr-failed`: файл может быть CLEAN, но OCR завершается ошибкой; доступен ручной ввод.

Файл с `unsafe` в имени либо тестовой строкой EICAR в демо получает FAILED. Это проверка поведения интерфейса, не настоящий антивирус. Файлы до перезагрузки удерживаются в памяти и выдаются только через разрешённый API.

Mock-данные живут **только в памяти вкладки** и сбрасываются при перезагрузке/закрытии. Это не доказательство долговечности. В sessionStorage остаются только ключи/метаданные команд, без body, финансов, токенов и файлов. Реальный backend должен хранить снимки, операции и сессии самостоятельно.

## 7. API и интеграция

Исходные контракты GitHub недоступны без авторизации. Поэтому клиент и типы **временные**, а integrated по умолчанию заблокирован. Названия финансовых полей и статусов не выдаются за канонические. Полное описание ожидаемых маршрутов, CAS, SSE и вопросов backend-команде — [docs/INTEGRATION.md](docs/INTEGRATION.md).

После получения OpenAPI нужно сгенерировать типы/клиент и адаптировать границу API. Экранные компоненты сохраняют feature-структуру. Сначала согласуйте финансовые поля/единицы, auth/CSRF/company context, статусы, версии RFI, uploads/OCR, operations/replay, SSE/gap/pagination и RAG.

## 8. Проверки

```powershell
npm test
# В другом терминале должен работать npm run dev
npm run test:e2e
# Все отдельные сценарии на временном порту 5180
node tools/verify-scenarios.mjs
```

Playwright использует установленный Google Chrome (`channel: chrome`), desktop 1440×1040 и mobile 390×844. Если Chrome отсутствует, установите браузер Playwright и измените `channel` в конфигурации. Основные e2e требуют `success`; отдельные сценарии запускает verify-scenarios.mjs. Сводка фактически выполненных проверок — [docs/VERIFICATION.md](docs/VERIFICATION.md).

## 9. Границы и ограничения

- Настоящие backend/ML/БД/банковские операции не реализовывались. Кредитное решение в mock определяется сценарием.
- Integrated API, CPU RAG/OCR, server authority, session durability и multi-tab cookie-session не проверены.
- В mock каждая вкладка имеет собственный store; BroadcastChannel на клиенте не превращает его в общий сервер.
- OCR — согласованное предложение искусственных значений. Помощник — детерминированный mock с разрешёнными источниками, не реальная LLM/RAG.
- Для backend с 202/PENDING потребуется согласованный polling/operation DTO. Клиент уже умеет искать потерянный результат по ключу и сверять серверный список, но не объявляет незавершённую операцию успешной.
- Правила eligibility, восемь финансовых полей и переходы временные. Их надо заменить реальными контрактами, а не дополнять случайной банковской логикой.
- Полная проверка WCAG, других браузеров, нагрузки и банковского допуска не выполнялась.
- Внешнее размещение потребует HTTPS, безопасных cookie, reverse proxy и integrated-приёмки. Публикация не выполнялась.

## 10. Что передать команде

Передайте исходники, package-lock, docs/REQUIREMENTS.md и docs/INTEGRATION.md. Не включайте node_modules в репозиторий. Сначала согласуйте provisional-v1 или замените его generated-клиентом исходного OpenAPI; затем проверяйте cookies, версии, RFI, документы, SSE и идемпотентность с настоящим backend. Результаты mock-тестов не заменяют эту проверку.
