# Подключение UI к фактическому backend

`api.ts` — небольшой клиент исполняемых API интеграционного MVP. Вызывает тот же origin с cookie, CSRF и выбранным контекстом компании; секретов ML в нём нет. Origin страницы должен входить в `credit.demo.allowed-origins`; demo-профиль разрешает localhost:5173 и 127.0.0.1:5173.

Клиент использует `/api/v1/*`, `If-Match: "vN"`, восемь полей в копейках и точные версии документов. `sourceDocumentReferences` не равно provenance: подтверждение и происхождение формирует backend. GET формы возвращает `containerVersion`; его следует использовать для CAS.

Отдельный UI в соседней рабочей папке `../frontend` использует provisional-v1: другие пути, статусы и поля финансов. Он не включён автоматически в эту поставку. Для его подключения нужно заменить API-adapter и отображение статусов; переименование URL не обеспечивает совместимость. Этот клиент проверяет границу интеграции, но не означает, что полный UI уже принят.

Перед VIEW интерфейс подтверждает видимость >=50% в течение >=1000 мс. HELPFUL/NOT_INTERESTED заменяют последнюю реакцию. Повтор события сохраняет исходные `clientEventId`, `occurredAt` и тело. Смена компании очищает текущие страницы; смена предпочтений делает прежние cursor недействительными.
